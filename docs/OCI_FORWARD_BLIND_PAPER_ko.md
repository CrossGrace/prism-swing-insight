# OCI홀딩스 미래 시점 블라인드 모의매매 — 사전등록 및 실행 계약

2026-11-19 현재 **코드·오프라인 테스트만 준비됨**. 실제 PRISM KIS MCP 데이터로 첫 관측을 실행한 기록, 지속 스케줄, 주문 체결, 수익률은 **아직 없음**. PDF 생성 작업은 하지 않는다.

## 앞선 연구와 구분

- 기존 **+37.60%**: 2026-06-17~11월 구간을 이미 확인한 뒤 고른 18개 규칙 중 최고 과거 복기. PRISM 전체 매매 엔진 결과도, 블라인드 수익률도 아니다. 이 수치를 새 원장이나 예상 성과로 사용하지 않는다.
- 이 시스템의 **정직한 블라인드 범위**: 11월 19일까지 관측한 시장·종목 지식으로 **사전에 고정한 규칙**을 미래에만 평가한다. 학습 과정 자체가 역사적 눈가림이었다는 뜻은 아니다. 시작 날짜 이전의 가격은 RSI 초기화에만 사용하고 매매 실적으로 기록하지 않는다.
- 첫 관측일은 원장 생성 당시 한국 시각 기준 **미래 영업일**이어야 한다. 예컨대 2026-11-19에 준비한다면 2026-11-20부터 가능하다. 토·일 시작은 금지하며 휴장일 지정은 실제 가격 수신 실패로 드러날 수 있으므로 사전에 거래소 일정을 확인한다.

## 이 구현에서 진짜 PRISM을 쓰는 범위

| 역할 | 호출하는 기존 코드 | 최종 판단권 |
|---|---|---|
| OCI·코스피 확정 일봉 수신 | `swing_insight/sources.py` → `prism_core/report_research_prefetch.py`의 `native_call` → PRISM `kospi_kosdaq` MCP의 `get_stock_ohlcv`·`get_index_ohlcv` | KIS MCP의 날짜·값 검증; 실패하면 거래 기록 중단 |
| 시장 상태 판정 | `swing_insight/market.py` → 기존 `cores/market_pulse.py` | 관측·로그 전용. `CORRECTION`은 이 별도 역발상 레인의 자동 매수 금지 조건이 아님 |
| OCI 후보·RSI·현금·가상 매수/매도 | **새** `swing_insight/blind.py` → `swing_insight/simulator.py`의 Wilder RSI와 보수적 OHLC 청산 모델 | 고정 결정론 규칙; PRISM 정규 BUY/SELL 에이전트는 호출하지 않음 |
| 거래 일지·봉과 결정 당시 증거 | 별도 `blind_study`, `blind_events` SQLite, 이벤트 SHA-256 연결 | 종목·정책·코드 해시를 봉인; 데이터 원본 스냅샷 포함 |

**중요:** PRISM의 **MCP 자료 수신 및 MarketPulse 재사용**이지, 기존 PRISM 주식 선정 → LLM BUY 판단 → `buy_gate` → KIS 실제 주문 → 보유 SELL 엔진을 통째로 실행하는 것은 **아니다**. 별도 연구 경로에서 기본 운영 전략을 변경하지 않는다. KIS 설정 파일(`trading/config/kis_devlp.yaml`)이 현재 작업 공간에 없어 MCP 통합 실행은 검증하지 못했다. OpenAI API로 뉴스와 기업 펀더멘털을 검토하는 별도 읽기 단계는 후속 범위이며 현재 블라인드 매수 판정에는 연결하지 않았다.

## 일봉 기반 신호 및 제약 (최초 원장 생성 후 고정)

1. 관심 종목: OCI홀딩스 **010060** 단일. 자본은 현금 100%로 시작하고 동시에 한 포지션만 보유. KOSPI 시장 상태는 증거로 저장.
2. 한국장 **16:10 이후**, 같은 날짜의 OCI·KOSPI 확정 일봉이 모두 실제 PRISM MCP로 제공된 경우에만 그 날짜의 신호를 기록. 오늘 데이터가 없다면 `MISSING`으로 중단. 중간 거래일을 놓쳤으면 사후 조회로 정상 실행한 것처럼 메우지 않음.
3. OCI 당일 종가가 전 거래일 종가 대비 **6% 이상 하락**하고 **Wilder RSI(14) ≤ 40**이면 `PAPER_SIGNAL_NEXT_SESSION_OPEN`을 기록. 종가를 보고 당일 시가에 소급 매수하지 않음.
4. 다음 거래일의 **시가**를 이용해 정수 주식 수로 매수 체결을 **사후 추정**. `매수가 = 시가 × (1+슬리피지)`; 매수 수수료를 포함해 현금 한도 내 최대 수량.
5. 고정 손절률·익절률·최대 보유 **0~3 거래일**을 적용해 그날 확정된 고가/저가/시가/종가로 청산을 **사후 추정**. 같은 일봉에서 손절·익절 둘 다 닿으면 손절 먼저, 시가가 손절가 아래로 갭 하락하면 손절가가 아닌 실제 시가 기준. 매도 수수료·세금·슬리피지 차감.
6. 별도 주문 실행기·`BUY`/`SELL` API 호출·자동 스케줄러는 **없음**. 위 `PAPER_*` 기록은 거래소나 증권사에 주문된 것이 아님.

이 방식은 **전방 관측(next-day paper replay)** 이지만 **장중 실시간 모의 체결이나 분봉 재현이 아니다**. T+1 시가를 T일에 알지 않고, T+1 종가 확정 이후 그날의 가정 주문을 기록한다. 특히 손절·익절이 동시에 닿는 일봉은 사건 순서가 불명이라 손절 우선으로 근사한다. 실제 체결 가능성·미끄러짐을 입증하려면 타임스탬프 있는 1분/5분봉, 가격 단위 및 호가/체결 이벤트 수집이 필요하다. 현재 PRISM MCP의 해당 일봉 도구에는 분봉 경로가 없다.

## 사전 결정해야 할 숫자 및 수동 실행 예시

`stop_pct`, `take_pct`, `max_hold_days`, `capital`, `fee_bps`, `sell_tax_bps`, `slippage_bps`는 **필수 입력**. 코드는 과거 18개 중 최고 수익률에서 숫자를 자동 채택하지 않는다. 아래는 **명령 구조를 설명하는 예시일 뿐, 사용자 확정 정책/실행 기록이 아니다**.

```bash
# 다음 명령은 2026-11-19에만 '미래 시작일' 조건이 성립하는 예시.
# 시작일과 모든 금액·비용 수치는 반드시 승인된 실험 계약으로 대체.
python -m swing_insight --db runtime/oci_forward_01.sqlite blind-init \
  --start-date 2026-11-20 --capital 10000000 \
  --stop-pct 5 --take-pct 8 --max-hold-days 3 \
  --fee-bps 10 --sell-tax-bps 20 --slippage-bps 10

# 시작 이후 각 거래일 당일 16:10 KST 이후 직접 실행; 놓친 날은 복기 금지.
python -m swing_insight --db runtime/oci_forward_01.sqlite blind-step \
  --as-of 2026-11-20

python -m swing_insight --db runtime/oci_forward_01.sqlite blind-status
```

최초 `blind-init`은 `PREPARED_NOT_RUNNING`; 첫 실제 MCP 관측 성공 후에만 `PAPER_OBSERVATION_STARTED`. 정책·해당 코드 SHA-256이 달라지면 기존 원장에서 새 거래를 추가할 수 없다. SQLite 업데이트/삭제 트리거와 이벤트 연결 해시는 실수·일반적 변조를 감지하지만 관리자가 DB 자체를 교체할 수 없는 보안 저장소까지 제공하는 것은 아니다. 신뢰가 중요하면 해시를 외부 서명 원장에 주기적으로 앵커링해야 한다.

`blind-status`에서 확인할 항목: 관측 거래일 수, 미청산 포지션, 완료 거래 수, 승·패, 이긴 거래 평균·진 거래 평균·손익비, 수수료 및 가정 슬리피지 반영 후 평가금액·수익률·최대 낙폭, 직전 증거 해시. 단 **실제로 한 번도 관측하지 않았으면 수익률은 `null`**.

## PRISM 전략 도입 검토 — 최소 여섯 항목

1. **유형/기준선:** 경제적 판단 규칙 신규 제안(기존 운영 전략 수정 없음). 원본 PRISM은 오닐식 추세추종·큰 주도주 장기 포착; 새 연구는 OCI 하락 당일의 짧은 역발상 스윙.
2. **가설/반증:** OCI의 펀더멘털 검증이 별도로 유지된다는 전제에서 급락+RSI 과매도 다음 0~3세션 반등이 손절 비용 이상으로 반복될 수 있다. 반증: 30개 이상 완료 거래 후 손익비 ≤ 1 또는 수수료 포함 기대 손실, 반복 손절·큰 낙폭. 최초 30건 전에는 우월성 판단 보류.
3. **기존 전략 궁합:** `trigger_batch.py`의 선별과 `cores/agents/trading_agents.py`의 LLM BUY, `cores/buy_gate.py`의 관문, `prism_core/order_budget.py`의 주문 예산, `stock_tracking_agent.py`·`tools/hardstop_seller.py`·`tools/trend_exit_seller.py`의 보유/매도는 **새 연구에서 우회**(운영 변경 없음). `cores/market_pulse.py`는 관측 목적으로 재사용. 일반 PRISM의 추세추종과 이 역발상 단타는 보유 기간·수익 목표·시장 국면에서 충돌하므로 합치지 않고 별도 레인 유지. 실제 BUY→관문→주문→SELL 통합 시나리오는 **미검증**. 100% 한 종목 가정은 실거래 위험 한도가 아니라 연구 시나리오이며 운영 승인이 아님.
4. **비교·반례·시점성:** 과거 +37.60%는 비교 기준에서 **제외**. RSI만 낮고 하락폭이 작거나, 지수가 하락하는 반례와 신호가 정상인 사례를 오프라인 테스트에서 확인. 월별 시장 국면, 동일 기간 OCI 단순 보유 및 현금 보유를 나란히 기록하되 실험 시작 뒤 규칙을 다시 고르지 않음. 실제 0~3일 성과 검출력은 30건에서도 제한적이며 독립 표본·시장 회귀가 부족함.
5. **원인 분리·중단/유지:** 매 거래일 판단 당시 원본, PRISM 시장 상태, RSI, 매매 비용, 손절·익절 이유를 고정 저장. 비용 가정 오차·데이터 장애·시장 하락/횡보·신호 자체 실패를 구분. 데이터 누락 시 중단하며 과거 결과에 맞춰 정책 재조정하지 않음. 재설계 시 새 원장/새 미래 시작일; 최소 30 완료 거래 이후 손익비·승률·낙폭과 매도 시나리오를 함께 보고 유지/중단 재결정.
6. **현재 판단:** **사전등록용 코드·오프라인 검증 완료, 관측 전 대기(HOLD)**. SHADOW/LIVE 편입 없음, 실제 거래 없음, PRISM KIS MCP 실통합 미확인. 사용자 위험·비용 수치 승인과 데이터 연결 및 일정에 대한 별도 확인 후 첫 미래 세션 관측.

## 안전 테스트

`tests/test_blind_swing.py`는 (a) 미래 시작과 코드/정책 고정, (b) 미래봉·당일 미확정봉·누락 세션·오염된 데이터 거절, (c) 다음 세션 시가 진입, 동일 일봉 손절·익절 충돌 시 손절 우선, (d) 사후 소급 거래 금지, (e) 거래 원장 해시·삭제/수정 차단, (f) PRISM MCP 장애 시 중단을 오프라인 가상 가격으로 검사한다. 이는 **실데이터를 이용한 블라인드 매매 성과나 KIS 연결 성공 증거가 아니다**.
